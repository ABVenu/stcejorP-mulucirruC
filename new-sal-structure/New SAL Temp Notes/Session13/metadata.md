title: SQL — Joins: Connecting Relational Tables

objective: Connect two related tables with INNER, LEFT, RIGHT, and FULL OUTER JOIN using a clear ON condition.

type of session: mixture of theory + implementation

topics be covered:
Why related tables exist; primary key and foreign key in plain words; INNER JOIN; LEFT JOIN; RIGHT JOIN; FULL OUTER JOIN (also called FULL JOIN in some tools); the ON join condition. Practice on a small customers table and orders table.

detailed subtopics to be covered:
Why one wide table repeats facts and causes contradictions
Primary key as the row's own id, foreign key as the id stored in the other table
Sample customers and orders, including a customer with no order and an order with no customer
INNER JOIN keeps only matching pairs
LEFT JOIN keeps every left-table row and uses NULL when the right side has no match
RIGHT JOIN keeps every right-table row; it is the mirror of a left join from the other table
FULL OUTER JOIN keeps unmatched rows from both sides
ON pairs the keys; a later filter that rejects NULL can drop the unmatched rows a left join had kept
